### 1. engine.ts 字段引用错误 → runAgent crash

- **错误信息**：`[Agent] runAgent error: undefined is not an object (evaluating 'config.apiFormat')`

### 2. 流式输出未启用 → 整段文字一次性返回

- **现象**：前端收到模型回复时，整段文字（block）输出后才能看到，而非逐字/逐句流式显示。
- **根因**：`streamOpenAiChat` 函数中 `stream` 设置为 `false`，导致整个响应一次性返回，而非 SSE 流式。同时未使用 `parseSseStream` 处理流式响应。

- **教训**：流式输出需要三处同时正确：① body.stream = true ② stream_options 配置 ③ 用 parseSseStream 而非一次性 JSON 解析。缺任何一处都会退化为非流式。

### 3. 对话消息未持久化 → 重启后历史记录丢失

- **现象**：正常聊天后重启应用，从任务列表选原来的对话，看不到任何记录。
- **根因**：对话消息只存在于前端内存（solid-js store），后端 `storage.ts` 创建的 JSON 文件 `messages` 为空数组。`engine.ts` 运行后不会将消息写入存储，前端也没有回写逻辑。重启后从后端加载的对话自然无消息。
- **修复**：
  1. `storage.ts` 新增 `saveConversationData(id, { messages, agentCtx })` 方法，读取现有 JSON、更新 messages 和 agentCtx、写回文件。
  2. `http-server.ts` 新增 `PUT /api/conversation-data/:id` 端点，调用上述方法。
  3. `agentBridge.ts` 新增 `saveConversationData()` 函数，向后端发 PUT 请求。
  4. `ChatView.tsx` 的 `finishStreaming` 中，流式传输完成后调用 `saveConversationData` 将 messages 和 agentCtx 保存到后端。
- **教训**：前后端状态分离后，必须显式设计"前端状态何时回写后端"的时机。流式传输完成（finishStreaming）是自然回写点。

### 4. Settings 页输入字符即失焦

- **现象**：在模型设置页的输入框中输入一个字符，输入框立即失焦，需重新点击才能继续输入。
- **根因**：每次 `oninput` 触发后调用 `props.onChange`，该回调创建全新的 provider 对象（深拷贝 + 修改），导致 `ProviderEditor` 整体重渲染。`<For>` 组件检测到 `models` 数组引用变化，销毁并重建所有子 DOM，输入框被销毁重建自然失焦。
- **修复**：使用 `createStore` 管理本地可变编辑状态（`const [local, setLocal] = createStore({ provider: deepClone(props.provider) })`），输入时直接 `setLocal("provider", "models", mIdx, "id", value)` 就地修改 proxy 属性，不触发整体重渲染。仅在 `handleSave` 时通过 `props.onChange(local.provider)` 一次性提交。
- **教训**：Solid.js `<For>` 对数组引用变化极度敏感——引用变了就销毁重建所有子 DOM。内联编辑场景必须用 `createStore` 本地状态就地修改，不能每次输入都创建新对象。

### 5. deleteConversation 后列表不更新

- **现象**：点击 Sidebar 删除按钮后，conversation 从后端删除成功，但前端列表不刷新。
- **根因**：`deleteConversation` 中使用 `setState('conversations', produce((list) => list.filter((c) => c.id !== id)))`。Solid.js 的 `produce` 包装的是可变 proxy，`filter()` 返回新数组但不会修改原始 proxy，导致 UI 不更新。
- **修复**：改为 `setState('conversations', (prev) => prev.filter((c) => c.id !== id))`，函数式 setState 直接返回新数组替换旧值。
- **教训**：`produce` 适合就地深改（push、splice、属性赋值），不适合返回新数组替换顶层。替换整个数组必须用函数式 setState。

- `Bun.resolveSync` / `Bun.pathToFileURL` 在 Cottontail 下不可用，要换成 `node:path` 的 `resolve()`。

- fetch 在 Cottontail 下可用，支持 ReadableStream。

## 2026-09-01 深夜+ — 三大问题根治（Sidebar 响应式 + removeFolder produce 坑）

1. **侧边栏会话不显示**（"新对话不往左侧加"）根因：`<For each={convs}>` 的 `convs` 是每次 render 返回的新数组（普通函数），Solid 不把普通函数返回值当响应式源，store 变化后 `<For>` 不重渲染。修复：把按文件夹过滤+排序逻辑包进 `createMemo`（`conversationsInFolder(folderId)` 返回 memo），JSX 用 `convs()`。**教训：Solid 的** **`<For>`/`<Show>`** **的 each/when 必须是 signal 或 memo，不能用普通函数调用结果**
2. **文件夹删除按钮点击无效** 根因：`removeFolder` 里用 `produce((list) => list.filter(...))`，solid-js/store 的 `produce` 对"返回新数组替换顶层"的写法不生效（递归代理不提交顶层替换）。修复：改成函数式 `setState("folders", (prev) => prev.filter(...))`。**教训：需要替换整个数组时用** **`(prev) => ...`** **函数式 setState，produce 只适合就地深改**
3. **AI 回复空白** 端到端验证：浏览器 transport=http 下发送消息 → SSE 流式事件 `agent_start→text→usage→agent_end→done` 完整到达，assistant 消息完整渲染；reload 后消息从 localStorage 持久化恢复也正常。当前代码在干净浏览器环境不再空白
4. 新增 `tests/issues.spec.ts` 三大问题回归测试（会话进侧边栏 / 文件夹删除按钮 / AI 回复非空），**5 个测试全绿**（`npx playwright test`）

## 2026-08-31 — 框架选型 & 脚手架

- electrobun 2.0 的运行时已从 Bun 换成了 Cottontail（自研 JSC 运行时 + Zig）。electrobun.config.ts 中 `build.mainProcess: "cottontail"`。所以 `Bun.file()` 等 API **不可用**，要用 `node:fs`。

- electrobun 1.x 用 `BrowserView.defineElectrobunRPC`，2.0 改成了 `BrowserView.defineRPC`。

- Electron 的 `ipcMain.handle()` 在 electrobun 中对应 `BrowserWindow.defineRPC({ handlers: { requests: { ... } } })`。

- electronbun devkit 源码在 `.hutch/devkit/api/`，遇到 API 疑问直接看这里。

- 配置文件中 `electrobun.config.ts` 用 `build.copy` 把 Vite 产物拷到 views 目录下：`"dist/index.html": "views/mainview/index.html"`。

- HMR 模式需要先起 vite dev server 再起 hutch，比较麻烦。开发阶段用 `hutch run dev` 更稳定。
