	强度指令（work-v21）—— 渲染后拼在每次 LLM 请求尾部，不进 system prompt。理由见 code-v21/effort.md。
	clerk / reader / check 的 prompt.md 里不许出现任何强度相关的条件。
--}}
{{#if isRoot}}
<work_mode>
{{#if isLow}}
这次只有你一个人：数清材料，算完就产出，写完确认它在盘上，然后交付。不要为了稳妥把每份材料从头读到尾。
{{/if}}
{{#if isMedium}}
数清材料再动手。产出后把硬指标（金额、行数、条目数）自己用脚本重算一遍，对不上就改完再交付。
{{#if canDelegate}}数字容不得错时，可以派 `check` 用脚本独立复算（它看不到你的思路，把材料路径、成果路径、口径写全）。{{/if}}
{{/if}}
{{#if isHigh}}
材料多而杂时{{#if canDelegate}}先派 `reader` 把散在各处的字段抽成一张事实表（它读一堆原文，你只收一张表），{{else}}先自己把材料扫一遍、把要的字段列成一张表，{{/if}}再据此产出。
产出后这一步**必须**做，不能自己算完就算完：{{#if canDelegate}}派 `check` 从原始材料独立复算硬指标（合计、各小计、条目数），{{else}}自己用脚本从原始材料重算一遍，{{/if}}对不上的逐条改完再交付。
{{/if}}
{{#if isUltra}}
分阶段产出：先出一份，核对过再出下一份。一次全做完，数字错了你分不清错在哪一份。
{{#if canDelegate}}先派 `reader` 抽事实表；每阶段**必须**派 `check` 复算（这一步不能省）；互不重叠的几份可以并行派 `clerk`。{{/if}}
交付前逐条回读用户原话：格式（文件名、列名、顺序、单位）、口径（含税与否、作废项算不算）、被剔除的条目是否都列了。每一条都要对得上，对不上的照实写。
{{/if}}
</work_mode>
{{else}}
<sub_task>
{{#if isLow}}
只做父 Agent 交给你的这一段，照抄原文不要改通顺。做完就用 `finish` 交代。
{{/if}}
{{#if isMedium}}
只做父 Agent 交给你的这一段：数字用脚本算，不要用脑子算。做完 `finish`。
{{/if}}
{{#if isHigh}}
只做父 Agent 交给你的这一段，数字一律用脚本算。发现段外的问题写进 `finish` 备注，不要自己动手。
{{/if}}
{{#if isUltra}}
只做父 Agent 交给你的这一段，口径严格按父 Agent 给的写，有歧义就在 `finish` 里点出来而不是自己拍板。若父 Agent 给了阶段划分，只做当前阶段。
{{/if}}
</sub_task>
{{/if}}
