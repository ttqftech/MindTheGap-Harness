{{!--
	强度指令（code-v21）

	这份文件**不是 system prompt**，它渲染出来后拼在每次 LLM 请求的**尾部**（排在动态状态之前）。
	原因：提示词缓存是「tools → system → messages」的前缀结构，改 system 一个字就会让后面整段历史
	全部 miss；而改尾部消息只影响尾部自己 —— 于是「强度」可以在会话中途切换而不炸掉缓存。

	所以：dev / explore / check 的 prompt.md 里**不许出现任何强度相关的条件**，强度只写在这里。
--}}

<work_mode>
{{#if isLow}}
这次只有你一个人，也没有委托工具：读完就改，改完跑一条验证命令，然后直接交付。不要为了稳妥把相邻文件都读一遍，不要写计划，不要分阶段。
{{/if}}
{{#if isMedium}}
这次你一个人做完整件事。收尾前把用户的每一条要求对着实际结果过一遍，有一条对不上就回去改，不要把它写进「没做的」里蒙混。
{{#if canDelegate}}想让改动之外的眼睛看一遍时，可以派 `check` 独立验证（它看不到你的思路，把命令与判据写全）；除此之外不要派活。{{/if}}
{{/if}}
{{#if isHigh}}
先摸清再动手：{{#if canDelegate}}不确定影响面就先派 `explore`，它的价值是上下文隔离——它读一堆文件，你只收结论；{{/if}}影响面清楚了就直接自己改。
改完这一步**必须**做，不能自己跑通就算完：{{#if canDelegate}}派 `check`，让它用 `git diff --stat` 看改动面、自己跑一遍测试，并核对需求里的每条行为是不是真有了。它报的「必须改」逐条改完再交付。{{else}}自己用 `git diff --stat` 核对改动面，再逐条核对需求。{{/if}}
{{#if canDelegate}}互不重叠的两块可以并行派 `dev`，但一个文件域只能有一个执行者。{{/if}}
{{/if}}
{{#if isUltra}}
分阶段推进：一批一个阶段，每阶段结束先核对改动面与测试，确认没跑偏再进下一批。不要一次把五处改动全改完。
{{#if canDelegate}}影响面不清就先派 `explore`；每阶段**必须**派 `check` 增量验证（这一步不能省）；互不重叠的文件域可以并行派 `dev`。{{/if}}
交付前逐条回读用户原话：每一条要求都要有对应的证据（命令输出或文件位置），对不上的照实写「没做到」，不要用听起来完成了的说法盖过去。
{{/if}}
</work_mode>
{{else}}

{{/if}}
{{#if isHigh}}
只做父 Agent 交给你的这一段，做的时候自己验一次。发现段外的必要改动写进 `finish` 的备注，不要自己动手。
{{/if}}
{{#if isUltra}}
只做父 Agent 交给你的这一段，改完自己跑一次验证再 `finish`。段外问题只报告不动手。若父 Agent 给了阶段划分，只做当前阶段。
{{/if}}
</sub_task>
