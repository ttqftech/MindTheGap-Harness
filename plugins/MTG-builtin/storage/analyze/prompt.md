# 三分类

把每一项归到且只归到一类：

- **A 可安全清理**：删掉不影响任何程序与数据。临时文件、缓存目录（浏览器 / 包管理器 / 缩略图）、过期日志、崩溃转储、可重建的构建产物（`node_modules` / `target` / `dist` / `build` / `__pycache__` / `.venv`）与包管理缓存。**条件是：能重新下载或重新生成。**
- **B 需用户确认**：删了能腾地方但有代价。大文件（视频 / 镜像 / 安装包 / 备份）、旧的下载物、很久没用但不明用途的目录、回收站、虚拟机与容器镜像、旧版 SDK / 模拟器运行时。
- **C 建议保留**：任何动了可能出事的。系统目录（Windows / `C:\Windows` / `C:\Program Files`、`/System` / `/usr` / `/bin` / `/etc`）、驱动存储、注册表相关、用户文档 / 桌面 / 图片 / 源码仓库、**当前正在被程序占用**的文件、以及你判断不出用途的东西。

判断不了归属 → 一律 C，并注明「用途不明，需用户确认」。

# 输出什么

用 `file_write` 写到 `{{workspaceDir}}` 下，文件名 `cleanup-plan.md`，结构是三张表 + 汇总：

每条写清：**路径 / 体积 / 类别（A·B·C）/ 删除方式 / 风险与代价 / 判断依据**

- **删除方式**三选一：
  - `回收站` —— 默认的推荐方式，删错了还能捞回来。
  - `备份移动` —— 体积大或回收站放不下的（回收站有容量上限），先移到 `{{backupsDir}}` 保存。
  - `保留` —— C 类。
- **风险与代价**：一句话说清删完会怎样（「首次启动会变慢 / 需要重新下载约 2GB / 会丢失离线数据」之类）。A 类也要写实，不许写「无风险」这种空话——代价至少是「重新下载 / 重新生成」。
- **汇总**：A 类合计可回收、B 类合计（需确认）、C 类不动；给出「只做 A 类」与「A+B 全做」两种口径的数字。

数字都来自盘点报告；报告里没有的不要自己造。需要补充判断时可以再跑只读命令核对（比如确认某个目录是不是某个软件在用），但不要重新全盘扫。

# 纪律

- 估算就是估算，写「约」。
- **不要为了多腾空间把 B 类往上抬成 A 类**。用户批准 A 类往往是一键同意，分类放宽等于替用户做决定。
- 同一路径的父子目录不要重复计入合计（比如同时列了 `node_modules` 和它的上级项目目录）。
- 报告里标注「未获取」的项，方案里就写「未能测量」，别猜数字。
