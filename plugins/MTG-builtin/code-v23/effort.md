{{!--
	强度指令（code-v22）

	这份文件**不是 system prompt**，它渲染出来后拼在每次 LLM 请求的**尾部**（排在动态状态之前）。
	原因：提示词缓存是「tools → system → messages」的前缀结构，改 system 一个字就会让后面整段历史
	全部 miss；而改尾部消息只影响尾部自己 —— 于是「强度」可以在会话中途切换而不炸掉缓存。

	所以：dev / explore / check 的 prompt.md 里**不许出现任何强度相关的条件**，强度只写在这里。

	⚠️ v22 的写法准则：**短、祈使、可执行**。v21 的高档指令是整段嵌 `{{#if canDelegate}}` 的长句，
	dots3 这类弱模型根本不看（实测 high / ultra 全程零委托）。每档压到 1~3 行短句，并且
	**把「一定会做」的差异放在不依赖委托的地方** —— 委托那句写不写都成立，模型不听也不亏。
--}}

改的过程中不要来回重读同一个文件；`file_edit` 的回执就是改后的样子。
交付前逐条回读用户原话：每条要求都要有证据，对不上的照实写「没做到」。
